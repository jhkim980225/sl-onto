# feature: 뷰 3종 — 계층·Table·RAW

> **캔버스 범위:** 세 뷰 모두 **현재 캔버스**만 본다 — 소스가 `GET /api/ontology` 로 받은
> `{nodes, edges}`(내부적으로 `allNodes()`/`allEdges()` 가 `currentCanvas()` 캐시를 집는다,
> [다중-캔버스.md](다중-캔버스.md))라서, 다른 캔버스의 객체는 애초에 클라이언트에 오지 않는다.

## 책임
같은 온톨로지를 그래프 말고 다른 각도로 보여준다 — Graph 외 3종:
**계층**(택소노미 트리) · **Table**(노드/관계 표) · **RAW**(JSON). 우하단 접이식 **오버뷰**
(타입별·관계별 카운트)는 네 뷰 모두 위에 겹쳐 뜬다. 상단 `[Graph | 계층 | Table | RAW]`
세그먼트(`components/ViewToggle.tsx`)로 전환 — `components/Workbench.tsx`의 `viewMode`
상태 하나가 어떤 뷰를 렌더할지 결정한다.

## 파생 모듈 — 전부 순수 함수, 프레임워크 비의존
```
lib/taxonomy.ts      buildTaxonomy(nodes, subtypeDefs) → TaxNode 루트(타입→서브타입→개체 3레벨)
lib/view-table.ts    buildNodeRows(view) / buildRelRows(view) → NodeRow[] / RelRow[]
lib/view-overview.ts buildOverviewCounts(view) → { byType[], byRel[], nodeTotal, edgeTotal }
```
셋 다 `{nodes, edges}` 스냅샷을 받아 구조·카운트·raw id만 계산한다 — **라벨 한글화·타입 색은
전부 컴포넌트**(`typeStyles.ts`의 `TYPES`/`TYPE_NAMES`, `relLabels.ts`의 `relKo`) 몫이라 store나
Next.js 없이 유닛 테스트가 된다(`lib/taxonomy.test.ts` · `lib/view-table.test.ts` ·
`lib/view-overview.test.ts`).

## 계층 뷰 — `lib/taxonomy.ts` + `components/HierarchyView.tsx`
`buildTaxonomy()`가 노드를 `TYPE_ORDER`(item→fm→cause→action→reg→proj→master→spec→doc) 순으로
묶고, 타입마다 `object_subtypes` 정의가 있으면 서브타입 그룹(정의 순 + "미분류" 그룹은 항상 마지막)
으로, 없으면 개체를 타입 직속으로 붙인다. 그룹 내 개체는 라벨 오름차순.

`HierarchyView.tsx`는 이 트리를 자체 구현 tidy-tree 레이아웃(SVG, `Graph.tsx`의 포스 시뮬과
완전 독립·새 의존성 없음)으로 그린다. 기본은 타입 9개만 펼쳐진 상태(`expanded` 집합) — 타입·
서브타입 박스 클릭은 펼치기/접기, 개체 박스 클릭은 `onSelectNode`로 그래프 포커스로 전환한다.
휠 줌·드래그 팬·"맞춤" 버튼을 직접 구현했다(뷰 전환 후 첫 표시에서만 자동 fit, 이후엔 사용자
조작을 보존).

## Table 뷰 — `lib/view-table.ts` + `components/TableView.tsx`
탭 2개: **노드**(타입·라벨·서브타입·속성 요약 최대 3개·근거 개수) / **관계**(시작·관계·끝, 라벨은
현재 뷰 노드에서 조회하고 뷰에 없는 대상 id는 원본 id 그대로 노출). `EVIDENCED_BY` 엣지는 관계
표에서 제외한다(근거는 노드 행의 "근거" 열에 개수로만 반영). 열 헤더 클릭으로 타입/라벨 정렬,
행 클릭 → `onSelect(id)`로 그래프 포커스.

## RAW 뷰 — `components/RawView.tsx`
현재 뷰 `{nodes, edges}`를 그대로 `JSON.stringify(view, null, 2)` pretty-print. 파생 모듈이
따로 없다 — 원본 그대로 보여주는 게 목적. 복사 버튼(`navigator.clipboard`, 실패는 조용히 무시).

## 오버뷰 — `lib/view-overview.ts` + `components/OverviewPanel.tsx`
`buildOverviewCounts()`가 타입별 노드 수·관계별 엣지 수(둘 다 내림차순, 동수는 입력 등장 순
유지)를 센다. 우하단 접이식 배지("현재 뷰 N객체 / M관계")로 항상 떠 있고 펼치면 타입·관계
목록. **좌측 타입 탐색기(전체 온톨로지 스코프)와는 숫자가 다를 수 있다** — 오버뷰는 "현재 뷰"
스코프(그래프 포커스·필터가 걸리면 그 결과만)라서 의도된 차이다.

## 확장 이음새
- 새 뷰 추가는 `ViewMode` 유니언에 한 값 추가 + `Workbench.tsx`의 뷰 분기 한 줄.
- 계층 뷰 레이아웃은 개체 수가 커지면(자식 다건) tidy-tree가 옆으로 넓게 퍼진다 — 가상 스크롤·
  접기 기본값 조정은 확장기.
- Table 뷰 정렬은 클라이언트 배열 정렬(모든 행 로드 후) — 페이지네이션은 범위 밖(1차 MVP 규모,
  180 노드/2,199 엣지 수준에서는 불필요).
