# feature: 문서 관리 — 캔버스 안의 문서 등록·교체·삭제

설계: [canvas-document-crud](../superpowers/specs/2026-07-20-canvas-document-crud-design.md)

캔버스는 문서를 부어서 채우는 워크스페이스다. 등록만 있고 교체·삭제가 없으면 잘못 넣은 문서를
되돌릴 방법이 DB 를 비우는 것뿐이었다.

| 동작 | 경로 |
|---|---|
| 등록 | `POST /api/ingest` (우측 📥 인제스천 패널, 드래그앤드롭) |
| 교체 | `PUT /api/sources/[file]` (좌측 📄 문서 드로어 `⟳`) |
| 삭제 | `DELETE /api/sources/[file]` (좌측 📄 문서 드로어 `✕`) |

## 삭제 규칙 — 근거가 0이 된 객체만 지운다
`lib/documents.ts` `deleteDocument(file)`:

1. `doc:<파일명>` 노드 삭제 → `EVIDENCED_BY` 엣지가 FK CASCADE 로 사라진다
2. 이 문서가 **유일한 근거**였던 객체만 삭제 → 그 객체의 엣지도 CASCADE
3. 다른 문서가 받치는 객체는 **유지**
4. `sources` 행(원본 바이트 포함) 삭제

골든 룰 1(근거 우선)의 직접적 표현이다 — 근거가 사라진 객체는 남을 이유가 없다.

**고아 판정은 삭제 전에 전부 계산한다**(`lib/documents.ts:26-31`). doc 노드를 먼저 지우면
`evidenceOf` 가 이 문서를 못 보게 되어 근거가 2개인 공유 객체까지 고아로 오판한다 —
**순서가 정확성의 일부다.** 회귀 테스트가 이 순서를 지킨다(`lib/documents.test.ts`).

## 알려진 한계 — 엣지에 출처가 없다
```ts
// lib/types.ts
export interface Edge { src: string; rel: string; dst: string; weight?: number; scen?: boolean }
```
`doc` 필드가 없다. 따라서 **"이 문서가 만든 엣지"를 원리적으로 특정할 수 없다.** 양끝 노드가 다른
문서에도 근거를 두면 그 문서가 그은 엣지도 그대로 남는다.

한때 "생존 객체 사이의 모든 엣지"를 `keptEdges` 로 보고했는데, 그 값에는 이 문서가 만든 적 없는
엣지(다른 문서·수동 큐레이션이 그은 것)까지 섞여 사용자가 읽는 의미와 달랐다. 지금은 **셀 수 있는
것만** 보고한다 — `keptNodes`(다른 문서에도 근거가 있어 유지된 객체 수).
정확 삭제가 필요해지면 `edges.props` 에 `docs[]` 를 기록하는 방향.

## 등록: 같은 파일명은 409
덮어쓰면 `sources` 행만 새 파일로 교체되고 `mergeDelta` 는 추가만 하므로 **옛 파일이 만든 노드가
그대로 남는다** — 그 노드들이 내용이 다른 문서를 근거로 갖게 되어 근거가 어긋난다.
`app/api/ingest/route.ts:84` 가 선제 차단하고 "⟳ 교체를 쓰세요"로 안내한다.

## 교체 = 삭제 + 재등록, 단 순서가 중요하다
별도 로직을 만들지 않는다. 다만 **파싱을 먼저 하고 성공했을 때만 삭제·병합**한다 — 순서가 반대면
파싱 실패 시 문서가 사라진 채 남는다.

거부 조건(전부 원본을 그대로 둔다):

- 파일명이 URL 의 `[file]` 과 다르면 **400**. 다르면 A 를 지우고 B 를 덮어써 A 가 통째로 사라진다
  (실측 노드 29 → 17). UI 는 "A 교체"라고 표시하므로 사용자는 모른다.
- **추출 객체 0건이면 400.** 이 레포의 파서는 견고 파싱이라 손상된 파일에도 throw 하지 않고 빈
  결과를 돌려준다(`data/real-samples` 대응). 그대로 진행하면 원본을 지우고 빈 델타를 병합해
  문서의 그래프가 통째로 사라진다 — **교체가 파괴 동작이 된다.** 실측으로 확인된 실패 모드다.
- 확장자(.xlsx/.pptx/.docx/.dxf/.pdf)·10MB·빈 파일 위반, 빈 스키마 캔버스(409 `needsSchema`).
- 파일명에 `/`·`\`·`..` 이 있으면 400(디렉터리 탈출 차단).

## UI
`components/DocumentPanel.tsx` — 좌측 레일 `📄` 드로어. 문서 목록 + `⟳` 교체 + `✕` 삭제.
삭제 확인 다이얼로그에 제거될 객체 수를 명시하고, 결과에 `keptNodes` 문장을 붙여 무엇이 남았는지
드러낸다. 등록은 우측 `IngestPanel` 전용으로 유지 — 등록은 드래그앤드롭이라 넓은 패널, 관리는
목록이라 좌측 드로어가 맞다.

## 한계
- 문서 버전 이력·롤백 없음. 교체하면 이전 내용은 회수 불가.
- `data/sources/` 베이스라인 문서도 삭제 가능하다. `default` 캔버스를 초기화하려면 DB 를 비우고
  재기동한다(기존 절차).
- 삭제는 store write-through라 DB 커밋이 실패하면 메모리도 안 바뀐다. 다만 doc 노드 삭제와 고아
  삭제가 **한 트랜잭션이 아니다** — 중간 실패 시 doc 만 사라진 상태가 남을 수 있다.
- `lib/documents.ts:5` 의 `allEdges` import 는 `keptEdges` 제거 후 미사용으로 남아 있다.
