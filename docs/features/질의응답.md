# feature: 질의응답 — 선택 객체 Q&A (RAG)

> **캔버스 범위:** `ai_opinions` 캐시 테이블이 `canvas_id`로 나뉜다(`lib/db.ts:501,517`) — 한
> 캔버스에서 만든 답변이 다른 캔버스로 새지 않는다.

## 책임
그래프에서 선택한 객체 하나를 두고 자유 질문하면, 그 객체의 속성·관계·근거 문서를 컨텍스트로
조립해 사내 LLM에 전달하고 인용이 붙은 답변을 받는다. `lib/ask.ts`(76줄)는 **컨텍스트 조립만
담당하는 순수 로직**(프레임워크 비의존)이고, 실제 생성은 `lib/llm.ts` `llmAsk()`가 pyservice
`/llm`(`task=ask`)에 위임한다.

## 골든 룰 — 컨텍스트만 근거로 답한다
LLM은 `buildAskContext()`가 만든 텍스트(객체 속성·관계·근거 문서 목록)만 근거로 답해야 하고,
**컨텍스트 밖 지식으로 임의 생성하지 않는다.** 이를 UI에서 검증 가능하게 하려고 관계마다
`R1..Rn` 번호를 매겨두고, LLM이 답변 본문에 `[R n]`으로 인용하면 `AskPanel`이 그 번호를 클릭
가능한 배지로 렌더해 근거 관계 칩과 그래프 포커스로 연결한다(`components/AskPanel.tsx:96-114`).
답변 하단에는 항상 "LLM 생성 초안 — 최종 판단은 엔지니어"가 붙는다(골든 룰 2, 확신도/검토용
명시).

## 컨텍스트 조립: `buildAskContext(objectId)`
1. `getObject(objectId)`로 객체 상세를 가져온다. 없으면 `null`(라우트가 404).
2. `EVIDENCED_BY` 관계는 "근거 문서" 섹션으로 따로 빼고, **도메인 관계에만 `R1..Rn` 번호**를
   부여한다(`domainRels = obj.relations.filter(r => r.rel !== "EVIDENCED_BY")`).
3. 상한: 관계 **`MAX_RELS = 30`**, 근거 문서 **`MAX_DOCS = 8`** — 컨텍스트가 커질수록 LLM
   프롬프트가 커지고 응답이 느려지므로 잘라낸다(`lib/ask.ts:8-9`).
4. 각 관계를 `R{no}: [관계 한글명/relId] A → B (상대 유형: ...)` 형태 한 줄로 렌더해
   `contextText`에 쌓는다.
5. 반환값 `AskContext = { object, rels, docs, contextText }` — `rels`·`docs`는 UI가 그대로
   렌더할 구조화 데이터, `contextText`는 LLM에 넘기는 평문.

## 캐시: `fnv1a` 해시 키
```ts
askKey(objectId, question) = "ask_" + fnv1a(objectId + "\0" + question.trim())
```
`lib/fold.ts`의 순수·결정론적 FNV-1a 32bit 해시(`lib/ask.ts:27-30`)로, `review-opinion` 캐시와
같은 관례를 쓴다. `POST /api/ask`는 이 키로 `ai_opinions`를 먼저 조회하고(`dbEnabled()`일 때만),
있으면 LLM을 호출하지 않고 즉시 반환(`cached: true`) — 같은 객체·같은 질문 재요청이 빠르다.
캐시 테이블이 `canvas_id`로 나뉘어 있어 다른 캔버스의 같은 객체 id·질문이라도 답이 섞이지 않는다.

## API: `POST /api/ask`
- body(zod): `{ objectId: string(1+), question: string(2..500) }`.
- 흐름: `buildAskContext` → 캐시 조회 → 미스면 `llmAsk(question, contextText)` → 성공 시
  `ai_opinions`에 저장.
- 응답: `{ answer, citedRels: number[], rels: AskRel[], docs: string[], cached, generatedAt, ms? }`.
- 객체 없음 → 404. LLM 실패/타임아웃(`maxDuration = 180`, 사내 vLLM 첫 생성 60~90초 여유) →
  503 `"사내 LLM 응답 지연·혼잡"`.
- 아키텍처 요약표(`docs/architecture.md` §4)는 입력을 `{id, question}`으로 적어두었지만
  **실제 스키마와 코드는 `{objectId, question}`이다** — 이 문서는 코드를 따른다.

## UI: `components/AskPanel.tsx`
- 객체 미선택 시 입력·전송·예시 질문 버튼 전부 비활성 — "질문은 썼는데 전송이 안 눌린다" 혼동을
  막는다.
- 대화 이력은 상위(Workbench)가 들고 있어 패널을 닫았다 열어도 유지된다. 각 항목에 질문 당시의
  객체 라벨을 태그로 남겨 "무엇에 대한 질문이었나"를 구분한다.
- 답변 본문의 `[R n]` 토큰을 정규식으로 잘라 클릭 배지로 바꾸고, 인용된 관계는 "근거 관계" 칩으로,
  나머지는 `<details>` 접기로 보여준다. 근거 문서 칩을 누르면 정형화 미리보기가 열리고 인용된
  관계 상대의 id·라벨이 하이라이트된다(`docHighlightIds`, `components/AskPanel.tsx:45-51`).

## 확장 이음새
- 지금 컨텍스트는 **온톨로지 노드(구조화 속성·관계)뿐**이다. 문서 원문 텍스트는 들어가지 않는다
  — `docs`에는 근거 문서의 **파일명만** 들어간다(`lib/ask.ts:53,70-73`).
- 문서 원문 청크를 컨텍스트에 추가하는 것은 별도 계획 문서로 분리돼 있다 →
  [원문-RAG.md](원문-RAG.md)(계획됨, 별도 엔드포인트 `POST /api/doc-ask` 설계). 이 `/api/ask`는
  그대로 두고 병행하는 설계다 — 객체 앵커 Q&A와 자유 질문 RAG는 성격이 다르다.
