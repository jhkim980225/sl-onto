# feature: 증분 인제스천

살아있는 온톨로지에 **새 문서 1건을 업로드하면 델타만 파싱·병합**되어 그래프에 실시간 합류한다.
"버튼 누르면 전체 생성"(데모 연출)이 아닌 **실제 운영 파이프라인의 축소판**을 보여주는 탭.

> **캔버스 범위:** 업로드·병합·삭제 전부 **현재 캔버스** 안에서만 일어난다(`withCanvasRoute` →
> `withCanvas` ALS). 다른 캔버스의 그래프·문서 목록은 영향받지 않는다.
> 설계: [multi-canvas](../superpowers/specs/2026-07-20-multi-canvas-design.md) ·
> [canvas-document-crud](../superpowers/specs/2026-07-20-canvas-document-crud-design.md).

## 흐름
상단 "📥 문서 인제스천" 탭(온톨로지 구축 후 활성) → 파일 드롭(.xlsx/.pptx/.docx/.dxf/.pdf, ≤10MB) 또는
**"샘플 문서로 시연"** → 결과: `새 객체 N · 새 관계 M · 기존 객체 연결 K · 전체 객체 totals` +
원문→표준 매핑·확신도 미리보기 → 그래프에 새 노드가 유형 구역 근처에 스폰(백본 뷰에서도 표시) → 좌측 원천 목록 갱신.

## 백엔드
- `lib/ingest/index.ts` `ingestOne(filePath, fileName)` — 단일 파일을 기존 파이프라인(정형 브랜치+휴리스틱+자유텍스트 폴백)으로 파싱.
- `lib/store.ts` `mergeDelta(nodes, edges, op?)` — **write-through**: DB(`persistUpsertGraph`)에 먼저
  upsert 하고 성공했을 때만 현재 캔버스 캐시에 병합한다(DB 실패 시 throw → 메모리 미변경).
  **멱등**(같은 파일 재병합 → 빈 델타). 기존 노드는 덮어쓰지 않음(원본 보존).
  새 노드가 생기면 임베딩 백필을 비차단으로 예약(`scheduleEmbedBackfill`).
  `registerSource`/`getRuntimeSources` 로 `/api/sources` 에 런타임 파일 노출.
- `POST /api/ingest` — multipart `file` 업로드 또는 `{"sample":true}`.
  샘플은 라우트(`handleSample`)가 SheetJS 인메모리 생성 — 매 클릭 차수 증가(`FMEA_현장보고_결로_n차.xlsx`)로 항상 새 델타가 생기고, 응답 `focus:"FMFOG"` 로 결로·습기 노드를 활성화.
  샘플엔 **신규 엔티티(auto-create 0.66)와 기존 엔티티 해소(결로·습기 FMFOG)** 가 함께 들어 있어 두 능력을 동시 시연.
- 응답: `{ ok, file, source, delta:{nodes,edges,updated}, totals }`.

### 거부 케이스 (409)
| 상황 | 응답 | 이유 |
|---|---|---|
| 캔버스에 객체타입이 0개 | 409 `{ needsSchema: true }` | `nodes.type` FK 가 막는다 — 스키마부터 정의해야 한다 |
| **같은 파일명이 이미 있음** | 409 `{ duplicate: true, file }` | 덮어쓰면 `sources` 행만 교체되고 `mergeDelta` 는 추가만 하므로 **옛 파일이 만든 노드가 남아** 다른 내용의 문서를 근거로 갖게 된다(골든 룰 1 위반). 교체는 아래 PUT 경로로. |

## 문서 삭제·교체 (`/api/sources/[file]`) → 상세 [문서-관리.md](문서-관리.md)
- `DELETE` — `deleteDocument(file)`(`lib/documents.ts`): doc 노드 삭제 + **근거가 0이 된 객체만** 삭제.
  다른 문서가 받치는 객체는 남는다. → [온톨로지-저장소.md](온톨로지-저장소.md)
- `PUT` (문서 드로어 `components/DocumentPanel.tsx` 의 ⟳ 교체) — **파싱 성공 후에만** 기존 문서를 지우고
  병합한다(원자성). 가드 2개: URL 파일명 ≠ 업로드 파일명 → 400(A 자리에 B 를 올려 A 가 통째로 사라지는 실측 실패 모드),
  추출 객체 0건 → 400(견고 파서는 손상 파일에도 throw 하지 않고 빈 결과를 주므로 그대로 진행하면 교체가 파괴 동작이 된다).

## 프론트
- `components/IngestPanel.tsx` (우측 패널 모드 "ingest") + Workbench 배선.
- `Graph.addDelta(nodes, edges)` — 유형 centroid 근처 결정적 시드 + spawn/pulse, **백본 뷰에서도 세션 추가분은 표시**,
  doc 노드는 캔버스 제외. 카운터(객체/관계/표시 중) 갱신.

## 검증
- 샘플: 매 클릭 새 델타(차수 증가), 미리보기에 신규(auto-create 0.66)+해소(기존 엔티티) 동시 노출.
- 멱등: 같은 델타 재병합 → 빈 델타. 실무 파일 multipart 업로드 동작.
- 테스트 스위트 전체: **140 tests / 133 pass / 7 skip**.

## 한계 (정직)
- **엣지 출처 미기록** — `Edge` 에 "어느 문서가 만들었는지"가 없어 "이 문서가 만들었지만 남은 엣지"는
  원리적으로 셀 수 없다. 그래서 응답은 셀 수 있는 것만 보고한다: `removed{doc,nodes,edges}` +
  `keptNodes`(다른 문서도 근거라 유지된 객체 수). 정확 삭제는 `edges.props.docs[]` 기록이 필요.
- 업로드 원본 바이트는 DB(`sources.content`)에 보존 — 재기동해도 살아있다. 베이스라인 `data/sources`
  파일들은 NULL(이미지에 원본이 들어있다).
