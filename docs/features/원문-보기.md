# feature: 원문 보기 — 근거 문서 원문 열람

> **캔버스 범위:** 현재 캔버스에 등록된 문서만 열린다 — `canvasSourceBytes()`가 이 캔버스의
> `sources` 목록에 없는 파일명은 디스크에 동명 파일이 있어도 거부한다(아래 "격리" 절).

## 책임
근거 칩(문서 파일명) 클릭 → 그 문서의 **전체 원문**을 재파싱 없이 그대로 보여준다. 골든 룰 1
(근거 우선)의 **마지막 확인 단계** — 인스펙터·체크리스트·Q&A가 보여주는 "근거: 파일명"이 실제로
무슨 내용을 담고 있는지 사람이 눈으로 대조할 수 있어야 근거 우선이 말뿐이 아니게 된다.

## 원문이 어디서 오는가 — 재파싱하지 않는다
업로드 원본 바이트는 인제스천 시점에 파싱만 되고 버려지는 게 아니라 `sources.content`(DB)에
그대로 보관된다([문서-관리.md](문서-관리.md)). `lib/source-text.ts`의 `extractSourceBlocks()`는
이 바이트를 받아 **블록 단위 텍스트**로 뽑아낼 뿐 온톨로지 추출과는 무관한 별도 경로다 — 파싱
로직 재사용(`readWorkbookGrids`/`readDeck`/`readDoc`)은 하되 결과를 노드·엣지로 만들지 않고
사람이 읽을 텍스트로만 돌려준다.

| 형식 | 처리 | 비고 |
|---|---|---|
| xlsx | 시트별 블록, 빈 셀만 있는 행 제외. `rows`(셀 그리드)와 `lines`(같은 행을 `│`로 이은 텍스트) 둘 다 실어 프론트가 실제 표로 렌더 | |
| pptx | 슬라이드 1장 = 블록 1개 | |
| docx | 전체를 "본문" 블록 하나로 | |
| pdf | 라우트가 직접 pyservice `/parse`를 호출해 본문+표를 합쳐 블록화 | `lib/source-text.ts`가 아니라 `app/api/source-text/route.ts`가 처리(async 사이드카 호출이라 동기 파서들과 결이 다름) |
| dxf | 빈 `blocks` — 원문 텍스트가 없는 형식(도면) | 415로 응답, UI가 도면 이미지 뷰로 대체 |

**폭주 방지**: 전체 라인 수가 2000행(`MAX_LINES`)을 넘으면 자르고 마지막 블록에
"… (이하 생략, 총 N행)"을 붙인다. xlsx는 잘린 지점에서 `rows`도 함께 잘라 표 렌더가 깨지지
않게 한다.

## API: `GET /api/source-text?file=<name>`
```
200 { file, format, blocks: [{ label, lines: string[], rows?: string[][] }] }
404 이 캔버스에 없는 문서
415 dxf(도면 미리보기 사용)
422 파싱 실패(어떤 입력에도 서버가 죽지 않는다 — catch 후 에러 메시지 반환)
503 pdf 인데 PYSERVICE_URL 미설정
```
`file` 쿼리는 `path.basename()`으로 정리해 디렉터리 탈출을 막는다.

## 격리 — DB 우선, 디스크는 폴백
`lib/source-bytes.ts`의 `canvasSourceBytes()`가 바이트를 내주기 전에 **이 캔버스의 `sources`
목록에 그 파일명이 있는지부터 확인**한다. 없으면 디스크(`data/sources/`)에 동명 파일이 있어도
`null`(→ 404)을 돌려준다. 순서도 중요하다 — DB(업로드분)를 먼저 보고, 없을 때만 디스크
(베이스라인 램프 문서)로 폴백한다. 이 순서가 바뀌면 두 가지 격리 위반이 되살아난다: ① 다른
캔버스에서 램프 베이스라인 원문·도면이 그대로 열림, ② 다른 캔버스가 같은 이름으로 문서를
올렸을 때 자기 문서 대신 램프 원문이 근거로 표시됨.

## UI: `components/SourceModal.tsx`
근거 칩·문서 드로어 클릭 → 전체 화면 모달. xlsx는 `<table>`, pptx/docx/pdf는 줄 단위 텍스트,
dxf는 `GET /api/drawing-svg` 도면 이미지(원문 텍스트 fetch 자체를 생략). Q&A·인스펙터가 인용한
토큰(`highlightIds`)이 있으면 원문에서 강조(표 셀 배경 `cell-hl` / 줄 안 `<mark>`)하고 첫 강조
위치로 자동 스크롤 — 없으면 현재 선택 객체의 라벨 + 관계 상대 라벨을 기본 강조로 쓴다
(`Workbench.tsx`의 `handleOpenEvidenceFile`). 강조 토큰은 길이 2 이상만, 긴 토큰 우선 정렬해
부분 매칭 겹침을 방지한다.

## 골든 룰 적용
근거 우선의 "근거"가 파일명 문자열에서 그치지 않고 실제 원문 대조까지 이어지는 지점이 이
기능이다. 다만 [원문-RAG.md](원문-RAG.md)가 지적하듯 이 원문은 **벡터화되지 않는다** — 이
기능은 "이미 알고 있는 근거 문서를 열어 확인"하는 경로이지, "원문에서 자유롭게 질문해 근거를
찾는" 경로가 아니다. 후자는 청킹 설계([원문-RAG.md](원문-RAG.md))가 맡는다.

## 한계
- pdf 는 pyservice 가용성에 의존(503) — xlsx/pptx/docx 는 pyservice 없이도 항상 동작.
- 강조는 정확한 문자열 포함 매칭뿐, 형태소·유사어 매칭 없음.
- 표 이외의 형식은 문단·슬라이드 단위 강조만 가능 — 셀 단위보다 거칠다.
