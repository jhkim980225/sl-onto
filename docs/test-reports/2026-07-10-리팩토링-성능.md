## 2. 성능 — 병목 실측·개선·검증

리뷰 실측 결론: **현 규모(180노드/2.2k엣지) 실질 병목 없음**(전 API <60ms, 고정비 ~26ms는 네트워크+라우팅). 실행 가치 2건만 조치:

| 항목 | before (v54) | after (v56) | 조치 |
|---|---|---|---|
| GET /api/ontology | avg 56.4ms · max 125ms · **201KB 비압축** | **avg 26.3ms · max 35.9ms · 전송 17.3KB(gzip, −91%)** | 라우트 직접 gzip — Next compress:true는 standalone Route Handler에 미적용(실측 확인) |
| 조회 API 공통 | avg ~30ms | **avg 14~15ms** | ready() 재동기화 TTL 2s — 창 내 연속 요청은 4쿼리+O(V+E) 재인덱스 생략. psql 직접 변경 반영 최대 2s 지연(새로고침보다 짧음 — DB 직독 체감 불변) |
| GET /api/search | 58.1ms | 41.3ms | (TTL 부수 효과 — 임베딩 왕복 +17~28ms는 기능 비용으로 수용) |

조치 안 함(측정 근거): quality 콜드 스캔 65ms — 그래프 크기 키 메모이즈 히트율 높아 무해(수천 노드 도달 시 foldKey Map 인덱스 예약) · contradictions/schema 스캔 ~4ms/~1ms · reason 168KB 왕복 — 캐시 히트 경로 30ms(콜드만, 라벨 제거는 pyservice 계약 변경이라 보류).
