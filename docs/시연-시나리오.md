# 시연 시나리오 — "스펙은 통과, 교차하면 모순" (v16 기준)

> 진입: **`http://192.168.0.100:30494/?update=1`** (온톨로지 구축 완료 상태로 바로 시작)
> 검색창에 질문을 입력하고 **Enter** = 자연어 질의. 아래 답변은 전부 라이브에서 검증된 실제 출력.
> 스토리 연출(카오스→구축)이 필요하면 파라미터 없는 기본 URL 사용(구축 연출 ~8초).

## 오프닝 멘트

> "FMEA는 활동인데 회사에는 문서만 남습니다. 저희는 문서를 다시 활동으로 되돌렸습니다 —
> 각각은 정상인데, 교차하면 숨은 리스크가 보입니다."

헤더의 **"⚠ 모순 9건" 배지**를 가리키며: "온톨로지가 스스로 찾아둔 모순입니다 — 질문하기 전에 이미 보입니다."
(클릭 → 전역 모순 스캔 패널: 기록 괴리·시장-환경·마스터 미참조, 각 항목 근거·confidence·경로 포함.
항목 클릭 → 그래프 포커스. 아래 2·4단계 대화는 이 배지의 각 항목을 파고드는 구성.)

옆의 **"🧹 정리 1건" 배지**도 함께: "모순만 찾는 게 아니라 — 자기 자신의 상태도 스스로 점검합니다."
(이어지는 "정리 배지" 장면에서 자세히.)

## 0. 도면 업로드 (컨텍스트 설정)

1. 헤더 **"📐 도면 분석"** → `data/sources/도면_신규_헤드램프_HL22.dxf` 업로드
2. 우측 패널: 추출 요약(부품명·프로젝트·**차종 SUV A**·소재) + 형상 특징 칩 7개
3. **유사 설계 카드**: `PJ 2021-HL12 [준중형 세단 B] 83%` — 일치 칩(✓벤트 2개 상·하 ✓이중 개스킷
   ✓밀폐형 슬림 ✓커넥터 근접) + 불일치(≠개스킷 소재) + **발생 이력: 결로·습기 · 수축 변형 · 배광 편차**
4. 멘트: **"이 모듈은 SUV A용입니다. 그런데 형상이 가장 닮은 건 세단 B — 차명이 아니라 형상이 말합니다."**

(원천 목록에서 도면 클릭 → 미리보기 → **🔍 크게 보기**로 실제 도면(NOTE·BOM·제목블록)을 전체 화면으로 보여줄 수 있음)

**도면 "추가" 장면(온톨로지가 자라는 모습)**: 📐 도면 분석 → **[▶ 샘플 도면 추가 — 신규 리어 콤비램프]**
→ 신규 프로젝트(PJ 2028-HL23)·신규 부품(테일 렌즈·리플렉스 리플렉터)이 **빨간 레이더 핑으로 스폰**되고
기존 부품(씰링 개스킷·방수벤트) 연결 + 형상 유사 SIMILAR 관계선(빨간 대시)이 합류, 카운터 174→179 객체.
멘트: "도면 한 장이 들어오면 온톨로지가 이렇게 자랍니다 — 새 지식은 빨간색."

## 1단계 — 형상 기반 유사 탐색

**질문**: `신규 헤드램프의 커넥터 실링 구조와 유사한 모듈이 과거에 있었나? 그때 습기 이슈가 있었나?`
(주어를 명시하면 업로드 순서와 무관하게 해당 도면으로 바인딩 — 리어콤비/안개등/DRL도 이름으로 질문 가능.
"이 …"로 물으면 마지막 분석 도면 기준. 답변 서두에 `[기준: PJ 2027-HL22 도면]`이 항상 표기됨)

**답변**:
> 네 — 형상 기준 83% 유사한 PJ 2021-HL12(준중형 세단 B)가 있습니다. 일치: 벤트 홀 2개(상·하) 일치 ·
> 실링 이중 개스킷 일치 · 하우징 밀폐형 슬림 일치. 해당 프로젝트에 **결로·습기** 발생 이력이 있습니다.

- 83% = 가중 특징 일치율(벤트 0.25·실링 0.2·하우징 0.2·커넥터 0.15·소재 0.1·렌즈 0.1) — 산식 공개, 블랙박스 아님
- 확장 멘트: "지금은 형상 *특징* 유사도, 다음 단계는 Milvus 지오메트리 임베딩 — 교체 지점이 설계돼 있습니다"

## 2단계 — 지역·환경 교차 (모순 ①)

**질문(선행 가능)**: `신규 헤드램프가 적용될 차종은 어느 시장(국가)향인가?` — 목표 시장 답변으로 진입
**질문**: `신규 헤드램프의 개스킷 등급이 목표 시장의 습도 조건 대비 충분한가?`

**답변**:
> **이 설계의 목표 시장은 아시아(동남아 포함)입니다(도면 제목블록).** 스펙만 보면 통과입니다 —
> 커넥터 IP67 등급, 벤트 2개소(상·하). 그러나 교차하면 모순이 드러납니다:
> 고온다습 지역(아시아 RH 80–95% · 중국 RH 75–95%)은 내부 결로 필드 클레임 빈발 지역(위험도 높음)이고,
> 형상 83% 유사한 PJ 2021-HL12(**동남아·중동향**)가 동일 벤트 구조로 **결로·습기 클레임 이력**을 갖고 있습니다.
> **등급 통과 ≠ 지역 환경 감당** — 벤트 용량 확대·하부 드레인·발수 코팅(아시아권 표준 대책) 재검토를 권장합니다.

- 이어서 결로 지역별 분석 화면(아우터 렌즈 → 🌫 결로 지역별 분석)으로 지역 기후·규제·설계도 심화 가능

## 4단계 — 소비자 반응 교차 (모순 ②)

**질문**: `신규 헤드램프와 유사한 차량에 대해 온라인 커뮤니티에 습기·김서림 언급이 있었나?`

**답변**:
> 네 — 커뮤니티 언급이 있습니다: PJ 2020-HL09 "김서림" 4건(동남아·여름) · PJ 2019-HL07 "습기 맺힘" 5건 ·
> PJ 2021-HL12 "김서림" 7건. **주목할 모순: PJ 2020-HL09는 FMEA 기록상 결로·습기 이력이 없는데
> 커뮤니티에 "김서림" 언급이 있습니다** — 내부 기록과 실사용 간 괴리.

- 데이터는 합성(소비자반응_커뮤니티.xlsx) — "실 운영 시 커뮤니티 크롤러로 교체되는 슬롯"이라고 멘트

## 결론 — 추론 실행

1. 도면 분석 패널의 **[▶ 이 조건으로 추론 실행]** → 도면이 시드가 되어 형상 유사도 기반 체크리스트 재계산
   (CHECK 01 간극 — 형상 1위 PJ21의 대표 클레임 · CHECK 03 결로·습기 · CHECK 04 벤트·씰링)
2. **[📄 FMEA 초안 다운로드]** → 과거 활동이 미리 채운 DFMEA 워크시트(xlsx)
3. 클로징 멘트: **"설계 스펙은 기준을 통과했지만, 형상·지역·소비자 데이터를 교차하면 동일 리스크 재발
   가능성이 높다 — 각각은 정상인데 교차하면 보이는 것, 이게 온톨로지의 가치입니다."**

## BOM 정합성 — "행 하나하나는 정상인데"

1. 그래프에서 **헤드램프 어셈블리**(또는 BOM 있는 부품) 클릭 → 인스펙터 하단 **"BOM 정합성"** 섹션
2. finding 예: `구성 부품 CTE 불일치 — 하우징(PC) vs 실링 개스킷(실리콘)` **risk 95%** —
   재질 이력 경고(하우징 → 수축 변형 이력 trace) 포함, 근거 칩 = BOM 문서 + FMEA 시트
3. 멘트: **"BOM 한 장을 올리면 — 행 하나하나는 정상인데, 재질을 교차하는 순간 열팽창 모순과
   과거 수축 클레임이 튀어나옵니다."**
4. trace 칩 클릭 → 그래프에서 CONSISTS_OF·HAS_FAILURE 경로 포커스 (근거 증명 동선과 동일)

## 부품 앵커 추론 — "이 부품만 검토해줘"

1. 그래프에서 부품 노드 클릭(예: **LED 모듈**) → 비연관 노드는 가려지고 연관만 남음
2. 버튼이 **[▶ 'LED 모듈' 설계 검토]** 로 바뀜 → 클릭
3. 체크리스트 헤더가 "선택 부품 'LED 모듈' 고장 이력 기준"으로 바뀌고, 전 항목 desc가
   "선택 부품 LED 모듈 고장 이력 (관련도 90%)" — 유사 프로젝트가 아니라 **그 부품의 실제 이력**만
4. [📄 FMEA 초안 다운로드] → 파일명·대상도 그 부품(`FMEA초안_LED 모듈_…xlsx`), 행도 그 부품(+구성)으로 스코프
5. 멘트: **"전체 조건 추론과 부품 단위 검토를 같은 온톨로지에서 — 클릭 한 번으로 관점이 바뀝니다."**
6. 다른 부품 클릭 후 재실행하면 즉시 전환, 선택 해제(뒤로가기) 후 실행하면 기본 조건 추론으로 복귀

## 마스터 대조 — "사람의 누락을 잡는다"

1. 추론 실행 후 체크리스트 하단 **"마스터 대조"** 섹션
2. `결로 방지 설계 마스터 — 필수 5항목 중 1 커버 — '하부 드레인 홀' 외 2건 누락` +
   ✓ 벤트 2개소 이상 / ⚠ 하부 드레인 홀 · 발수 코팅 · 개스킷 내습 등급 / 기밀 시험 조건 미확인
3. 멘트: **"결로 마스터 표준은 필수 5항목 — 이번 검토안이 못 덮은 항목을 온톨로지가 잡아냅니다.
   애매하면 '미확인'으로 정직하게 표기합니다(오탐보다 안전)."**
4. 북미 조건으로 재실행하면 배광 마스터(MBEAM) 대조로 바뀜 — 조건 따라 살아있는 대조

## 정리 배지 — "문서 추가 → 온톨로지가 자란다 → 스스로 정리"

1. 헤더 **"🧹 정리 1건" 배지**(모순 배지 옆)를 가리키며: "온톨로지는 문서가 들어올 때마다 자랍니다.
   그런데 자라기만 하면 잡음도 같이 쌓입니다 — 이건 온톨로지가 스스로 찾아둔 정리 대상입니다."
2. 클릭 → 품질 스캔 패널: **`PJ 2027-HL22 — 고립 노드`**(확신도 55%) — 근거 문서(도면 2건)는 있지만
   아직 다른 객체와 연결(관계)이 하나도 없는 상태. "방금 들어온 신규 도면 프로젝트라 아직 그래프에
   편입되지 않은 겁니다 — 도면 분석·추론을 실행하면 SIMILAR·발생 이력 관계가 붙어 저절로 해소됩니다."
3. 스캔 규칙은 3종: **중복 후보**(자동 추출 `AUTO_*` 노드가 정식 노드와 표기만 다른 동일 개체로 보임 —
   확신도 92%) · **고립 노드**(근거는 있는데 관계가 0개, 위 2번 사례) · **근거 없음**(원본 문서 연결이
   아예 없는 상태 — 근거 우선 골든 룰 위반 탐지, 확신도 70%). 항목마다 `[병합→대상라벨]` / `[삭제]`
   버튼이 있고, 눌러야만 `POST /api/curate`가 실행된다 — 스캔 자체는 아무것도 자동으로 고치지 않는다.
4. 멘트: **"모순 스캔이 '데이터가 서로 말이 안 맞는다'를 잡는다면, 정리 스캔은 '온톨로지 자신의
   위생 상태'를 잡습니다 — 둘 다 질문하기 전에 이미 배지로 떠 있습니다."**

## 근거(provenance) 증명 — 질문 들어올 때

답변의 관련 객체 클릭 → 인스펙터(FMEA 요약 카드) → **근거 문서 행 클릭 → 원문 미리보기** (3클릭).
- 83%의 근거: 도면 NOTE(도면_신규_헤드램프_HL22.dxf) ↔ 유사도매트릭스.xlsx 형상특징 시트
- 결로 이력의 근거: `PJ21 —OCCURRED_IN→ 결로·습기` 엣지 ← FMEA_결로_지역별_검토시트.xlsx 행

## 단계 커버리지 (v15)

| 시나리오 단계 | 상태 |
|---|---|
| 1 형상 기반 | ✅ 대화 + 도면 분석 카드 |
| 2 지역·환경 교차 | ✅ 대화(모순) |
| 3 법규 교차 | 🔶 2단계 답변·결로 지역 화면에 부분 흡수 |
| 4 소비자 반응 교차 | ✅ 대화(모순, 합성 데이터) |
| 5 BOM 정합성 | ✅ BOM xlsx 인제스천 + `checkBom` (CTE 교차·재질 이력·밀폐+벤트) — Inspector item 카드 |
| 6 마스터 대조 | ✅ 결로 마스터(설계표준_결로체크리스트.xlsx) 필수 5항목 vs 체크리스트 커버리지 — 체크리스트 하단 ✓/⚠/미확인 칩 |

참고: 저장소가 **Postgres 영속**이라 파드 재시작에도 업로드분이 유지된다. 리허설로 쌓인 데모 잔여물을
지우고 초기 상태로 돌리려면 DB의 그래프 테이블을 비우고 재기동(비면 `data/sources` 재인제스천) —
`kubectl rollout restart`만으로는 초기화되지 않음. 시연 중 새로고침이 나면 `?update=1`로 즉시 복귀.
