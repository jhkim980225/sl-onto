**이미지 OCR(스캔 PDF·표 사진)**, **외부 크롤링**, **로그인·편집·HPA**.

> **배포 상태**: 클러스터 **v76(2026-07-20)** — 로컬 HEAD 와 동일. 001-canvas 마이그레이션이

## 1. 비정형문서 분석

### ① 문서 형태 분석 및 형태별 최적 파싱 — ✅ 됨 (텍스트 문서 범위)

단순 확장자 분기가 아니라 **문서 내부 형태까지 감지해 파싱 전략을 바꾼다** (`lib/ingest/`):

- **xlsx**: 정형 시트는 컬럼 매핑, 실무형 시트는 휴리스틱 — 헤더 행 자동 탐지(앞 15행 스캔),
  2행 병합 헤더, 세로 병합 셀 전파, 동의어 컬럼명 매핑(부품명/품명/item…)
- **pptx**: 앵커 섹션 파싱(프로젝트:/이슈:/원인분석/대책), 산문형 8D는 자유 텍스트 엔티티 스캔 폴백
- **docx**: "키: 값" 필드 파싱 + 산문 리포트 폴백
- 측정: 실무형 지저분한 샘플에서 구파서 **0객체/0관계 → 견고 파서 42객체/36관계** (`data/real-samples/`)

상세: [features/ingestion.md](features/ingestion.md)

### ② 문서·이미지 내 텍스트 파싱 → 데이터베이스 구축 — 🔶 절반

- ✅ **문서 텍스트 → 지식베이스**: 37개 문서 → 온톨로지 174 객체/2,171 관계, 전 객체 원본
  근거·확신도 연결. 증분 인제스천(새 문서 1건 실시간 병합)까지 동작.
- ✅ **PDF 인제스천**(v53): pyservice `POST /parse`(pypdf) 경유 텍스트 PDF 파싱. docling 은 lazy 옵트인.
- ✅ **영속 DB**: Postgres 이관 완료 — DB가 원본(source of truth), 인메모리는 읽기 캐시.
  최초 부팅 시 DB 비면 `data/sources` 인제스천 → 벌크 적재, 이후엔 DB에서 로드(업로드분 보존).
  pgvector 확장으로 노드 임베딩(384-dim)까지 저장. 프로덕션(v45)에서 가동 중.
- ❌ **이미지 내 텍스트(OCR)**: 스캔 PDF·표 사진·도면 주석 못 읽음 — Docling(Python 사이드카)/VLM
  확장 경계. 결로 설계도는 실도면 파싱이 아니라 온톨로지 링크된 SVG.

### ③ 외부 데이터 크롤링(논문·커뮤니티) — ❌ 안 됨

미착수. MVP 범위에서 의도적 제외, 확장기 분류 ([requirements.md](requirements.md) §4).

## 2. 문서 구조화 · 지식 온톨로지 구축

### ① 파싱 데이터를 LLM으로 부품/고장모드/원인/조치 필드 구조화 — 🔶 규칙 기본 · LLM 보강 옵트인

기본 엔진은 **결정론적 규칙**(`lib/ingest/normalize.ts`): 원문 → 표준 객체 매핑(통제 어휘 + 동의어
사전), 미등록 값 auto-create(id `AUTO_*`, 확신도 0.66), 원본값 보존 + 확신도 티어(1.00/0.95/0.82/0.72).

**LLM 보강은 v54 에서 실장**(`/api/ingest?llm=1` → `lib/ingest/llm-assist.ts`): 규칙 파서가 건진
객체가 3개 미만인 pdf/pptx/docx 에 한해 자유 텍스트를 LLM 에 넘겨 통제 어휘 카탈로그 기준으로
추출하고 델타로 병합한다. **기본 OFF** — 사내 vLLM 이 쿼리당 30~90초라 명시적 `?llm=1` 일 때만.

설계 판단(결정 기록): 좁고 통제된 도메인 어휘에서는 규칙이 더 빠르고 재현 가능하므로 규칙이 1차,
LLM 은 규칙이 실패한 문서에만 쓰는 폴백 위치에 둔다.

### ② 부품/고장모드/원인/차종/법규 등 객체·관계 정의 — ✅ 완전히 됨

- **객체 9종**: item(부품)·fm(고장모드)·cause(원인)·action(조치)·reg(법규)·proj(프로젝트, 차종은
  속성)·master(설계표준)·spec(고객스펙)·doc(근거문서)
- **관계 12종**: HAS_FAILURE·CAUSED_BY·MITIGATED_BY·UNDER_REG·DRL_REG·REF_MASTER·CONSISTS_OF·
  OCCURRED_IN·SIMILAR·THERMAL_RISK·SPEC_OF·EVIDENCED_BY (+ 시나리오 NEW_DESIGN_OF/TARGET_MARKET)

상세: [data-model.md](data-model.md)

## 3. 의미 기반 검색

### ① RAG 기반의 조건 필터 — 🔶 조건 필터 ✅ · 객체 Q&A RAG ✅ · 검색 랭킹 RAG ❌

두 갈래로 나뉜다.

- ✅ **RAG 실장(v51~)**: `POST /api/ask` — 선택 객체의 관계·근거를 `buildAskContext()` 로 모아
  LLM 에 넘기고 `[R n]` 인용이 붙은 답변을 받는다. 답변은 그 컨텍스트만 근거로 생성되고 인용
  근거(rels)를 함께 반환해 UI 가 노출(골든 룰). 결과는 `ai_opinions` 에 캐시(같은 질문 즉시 응답).
  검증 리포트 3건: [test-reports/2026-07-09-객체질문-RAG.md](test-reports/2026-07-09-객체질문-RAG.md) ·
  [기존문서 4/4 PASS](test-reports/2026-07-10-RAG-기존문서.md) · [신규문서 전 구간 PASS](test-reports/2026-07-10-RAG-신규문서.md).
  같은 패턴으로 `POST /api/review-opinion`(설계 조건 → 추론·모순 컨텍스트 → LLM 검토 소견)도 동작.
- 🔶 **검색·추론 랭킹**: 지역 필터(북미 질의에 유럽 법규 배제), 유형 의도 필터, 신규 설계 조건
  그래프 탐색(체크리스트)은 여전히 **검색 결과를 템플릿으로 조립** — R→G 가 아님. `infer()` 시그니처를
  유지한 채 내부만 교체하는 이음새는 그대로 ([features/inference.md](features/inference.md)).

### ② 벡터 의미 검색 색인 — ✅ 색인·하이브리드 후보 · 최종 랭킹은 규칙

pgvector 도입 완료: 전 노드 384-dim 임베딩(`paraphrase-multilingual-MiniLM-L12-v2`, Python
사이드카 pyservice) 색인. **자연어 검색에서 실사용** — 질의 임베딩 코사인 top-20을 후보로
넓힌 뒤 최종 랭킹·지역 필터는 규칙 스코어러가 결정(보수적 통합, 실패 시 규칙 폴백).
초기 시도였던 ollama `nomic-embed-text`는 한국어 변별 실패로 폐기, 다국어 MiniLM로 대체.
**v52 에서 키워드 검색도 하이브리드화** — `search()` 가 `semantic` 후보를 받고, 중복해소가
정식↔정식 88% + 임베딩 기준으로 강화됨. 최종 순위 결정권은 규칙 스코어러에 유지
([features/search.md](features/search.md) · [features/nlsearch.md](features/nlsearch.md)).

### ④ 형식 온톨로지 — ✅ (v49)

메타모델 확장 + 스키마 검증 엔진 + 서브타입 분류(61/139) + **Turtle 내보내기 3,007 트리플**
(`GET /api/schema` 읽기 전용 스냅샷, `/api/ontology/export`). 좌측 탐색기가 서브타입 라벨로 분기.

### ③ 웹에서 자연어 질의 — ✅ 됨

검색창 Enter → `POST /api/nlsearch`: 지역·유형 의도·동의어 해석 + 엔티티 링크 + 1-hop 그래프
확장, 해석 결과("지역: 북미 · 개념: 결로 · 유형: 조치")와 함께 응답. <1초. LLM 경로는
`NL_USE_LLM=1` 옵트인(사내 vLLM 지연으로 기본 OFF, 실패 시 규칙 폴백).

## 4. FMEA 초안 생성 (2D 도면 + BOM → 유사 사례 → 후보·체크리스트·근거 → 초안)

파이프라인 뒷단(②~⑥)은 전부 동작, **입력 앞단(①)만 대체 구현**.

| 단계 | 상태 |
|---|---|
| ① 입력: 2D 도면 이해 | 🔶 **DXF 실장**: `POST /api/drawing-input` 업로드 → 온톨로지 합류 + 형상 유사 과거 설계 탐색(SIMILAR 병합) + 조건 후보 제시, `GET /api/drawing-svg` 웹 미리보기, `lib/drawing-risk.ts` 설계 취약점 검사(열팽창 차이·벤트↔발열원 근접·IP 등급 vs 시장·밀폐 벤트 부족). **래스터/스캔 도면(PDF·사진) 이해는 여전히 ❌ — VLM 영역** |
| ① 입력: BOM | ✅ BOM xlsx 파서(`ingestXlsxBom`) — 동의어 컬럼 매칭(상위부품/모듈, 부품명/품명, 재질/소재), `CONSISTS_OF` 생성, 미등록 부품 auto-create, doc 근거 자동 연결 |
| ② 유사 조건 과거 사례 검색 | ✅ SIMILAR 가중(0.87 등) + 조건 매칭(광원·형상·시장) 스코어링 |
| ③ 고장모드 후보 | ✅ 유사 프로젝트 발생 이력 수집 + 조건 부스트(북미→FMVSS·슬림→수축·밀폐→결로) |
| ④ 체크리스트 | ✅ 근거·확신도% 붙은 상위 8 |
| ⑤ 근거 출처 | ✅ 항목마다 원본 문서 칩 + 실존 엣지 경로(trace) |
| ⑥ FMEA 초안 생성 | ✅ 13컬럼 DFMEA 워크시트(S·O·D·RPN·우선순위·권고조치·근거) 조건 맞춤 xlsx 다운로드 |

현재 입력은 텍스트 설계 조건(시장·광원·형상·대상 부품). 상세: [features/fmea-draft.md](features/fmea-draft.md) ·
[features/inference.md](features/inference.md)

## 5. 다중 캔버스 (확장 — 과제 원문 요구는 아님)

과제 원문에는 없는 **확장분**이다. "도메인(관련 부서·제품군)이 바뀌면 새 워크스페이스에서 자기
문서로 자기 온톨로지를 처음부터 구축할 수 있어야 한다"는 후속 요구에 대응했다.
구현·검증·배포 완료(**v76**, 2026-07-20).

| 항목 | 상태 |
|---|---|
| 캔버스 = 완전 격리 워크스페이스(데이터·스키마 0에서 시작) | ✅ 램프 지식이 새 캔버스로 새지 않고, 그 역도 없음 |
| 기존 데이터 귀속 | ✅ 179 노드 / 2,198 엣지 / 40 문서 → `default`(램프) 캔버스 |
| 캔버스 CRUD + 휴지통 | ✅ `/api/canvases` — 생성·이름변경·소프트삭제·복구·영구삭제(마지막 캔버스 삭제 409) |
| 캔버스별 스키마 정의 | ✅ `/api/schema/object-types` · `/api/schema/relation-types` + `◈ 스키마` 드로어 |
| 기능 가용성 자동 유도 | ✅ FMEA 타입 없는 캔버스는 추론·초안·모순·BOM 이 409 + UI 버튼 숨김(`lib/capabilities.ts`) |
| 캔버스 내 문서 삭제·교체 | ✅ `DELETE`/`PUT /api/sources/[file]` + `📄 문서` 드로어 |
| UI | ✅ 좌측 레일 드로어 4종(`▤ 캔버스` · `📄 문서` · `▣ 객체 타입` · `◈ 스키마`), 전환은 key 리마운트 |

**알려진 한계 (숨기지 않음)**

- **엣지 출처 미추적**: `Edge` 에 근거 문서 필드가 없어 "이 문서가 만든 엣지"를 특정할 수 없다.
  문서 삭제 시 양끝 객체가 다른 문서에도 근거를 둔 엣지는 **남으며**, 응답의 `keptEdges` 로 보고한다.
- **마이그레이션 단방향**: `001-canvas.sql` 은 되돌리기 스크립트가 없다. 회수 경로는 DB 백업뿐
  ([deployment.md](deployment.md)).
- **`condensation` 은 `default` 캔버스 전용**: 노드 id(`ILENS`·`FMFOG`) 하드코딩이라 일반화 전까지 고정.
- 캔버스 권한·소유자(로그인 없음), 캔버스 간 문서·노드 이동은 범위 밖.

## 발표용 요약 문장

- 비정형 분석: "사내 문서(xlsx·pptx·docx·**pdf·dxf**) 형태별 파싱과 **Postgres 영속 지식베이스**
  구축은 **동작 완료**, 이미지·스캔 OCR은 **Docling 연동 지점만 설계**, 외부 크롤링은 **미착수(로드맵)**."
- 구조화·검색: "규칙·그래프가 기본 엔진이고, 그 위에 **pgvector 하이브리드 검색**(한국어 다국어
  MiniLM)과 **LLM 보강이 실장**됨 — 객체 Q&A RAG(`/api/ask`, 검증 3건 PASS), 인제스천 LLM 보강
  (`?llm=1`), 검토 소견 생성. **LLM 은 옵트인**(사내 vLLM 60~90초) — 기본 경로는 1초 내 규칙, 실패 시 폴백.
  **형식 온톨로지**(서브타입 61/139 · Turtle 3,007 트리플)까지 나감."
- FMEA 초안: "유사 사례 → 고장모드 후보 → 근거 달린 체크리스트 → **채워진 FMEA 초안**(마스터
  대조 요약 포함)까지 생성 루프 완성. **BOM 입력 파싱·정합성 검증(CTE 교차)** 과 **DXF 도면 입력
  (형상 유사 탐색 + 취약점 검사)** 동작, 래스터 도면 이해는 장기 확장."
- 교차 검증(신규): "**전역 모순 스캔**(기록 괴리·시장-환경·마스터 미참조)이 헤더 배지로 상시 노출,
  **부품 앵커 추론**으로 부품 단위 검토, **마스터 대조**가 검토안의 누락 항목을 잡는다 —
  전부 근거·확신도 부착(골든 룰)."
